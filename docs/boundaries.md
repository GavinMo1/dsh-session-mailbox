# 已知边界

每条都写清「真撞上时看哪里、怎么办」——没有去处的边界不写在这里。取舍论证见 [DESIGN.md](../DESIGN.md)。

## 投递

| 边界 | 撞上时怎么办 |
|---|---|
| **`queued` 只表示「已进对方的收件箱」，不表示对方读到了。** 投递分两步（归因后塞进收件箱 → 落一次盘），第二步失败不影响第一步，也不会把已接收报成没送到。 | 要确认到达，让它回信，然后看 `list_sessions` 行尾有没有「已回信」。 |
| **对正在跑的会话，我们是插话，不是排队。** 没有参数可以指定「等它这一轮结束再送」；插话落在对方当前回合的下一步，而且不会抢占正在执行的那个工具调用。 | 想让它先做完再读，就先别发；或者等它 `inactive`。返回值里的 `primitive` 告诉你这次走了哪条。 |
| **归档的会话收不到消息**，也不会被冷路径拉起来。 | 先 `unarchiveSession`（或 GUI 恢复），再发。 |
| **单条消息上限 `maxBytes`（默认 65536 字节，按 UTF-8 算）。** | 拆两条，或调大 `maxBytes`。 |
| **只在同一个 Host 进程内。** 不同 DSH 实例、桌面端与 web/qqbot 之间互不可见，各有自己的一套会话和记账文件。 | 跨进程协作没有支持；别指望在 web 端看到桌面端的「已回信」。 |
| **消息不代表授权。** 消息里没有任何可表达权限的字段，对端是「按它自己的权限判断」，不是机制拦截。 | 需要限制谁能给谁发，用配置里的 `allow`。 |
| **插件不数跳数。** 两个守规矩的 agent 真打起了乒乓球，插件不会拦。 | 这是约定问题：拿到结论就回到人这里，别自动互相回下去。 |
| **插件没挂上的那一小段时间，收信方回不了信。** 判断方法是看工具表里有没有 `send_session_message`。 | 那时只能由人在 GUI 里打字，或者打开插件 / 重启 DSH。 |

## 名称与地址

| 边界 | 撞上时怎么办 |
|---|---|
| **标题是快照，也不是地址。** 消息头里那行 `来自「标题」` 是发送那一刻的标题；之后改名不会改写已投出去的消息。同名的会话可能有多个。 | 要长期引用某个会话，用完整 `id`。标题撞车会报 `ambiguous` 并给候选。 |
| **冷会话只能按完整 id 点名。** 它的标题和短名要靠活会话表，冷态下解析不出来。 | id 从 `list_workspaces` 的展开行拿（`session: <id>`）。 |
| **冷会话装载进内存之后不会卸载**，直到 DSH 重启。 | 正常使用不用管；会话特别多时注意这是常驻内存。 |

## 回信状态（行尾那半句）

| 边界 | 撞上时怎么办 |
|---|---|
| **「未回信」是可见性，不是收据。** 它只说明「经本插件发出的最后一条之后，对方没有经本插件回过」。对方用别的路子回你（用户自己打字、别的插件投递），这里看不到。 | 查 `peers.json` 里有没有 `对方id\|自己id` 那条边。路径见[机制](mechanism.md)里「已回信 / 未回信怎么来的」一节。 |
| **从没被本插件发过消息的会话，行尾什么都不会多。** 这是设计，不是漏显示。 | 不用管；这恰好说明它没被派过活。 |
| **记录读不到就当作「无记录」，绝不标「未回信」。** 文件缺失、坏掉、版本不认识时列表照常出，只是没有后缀。 | 「没后缀」和「没回过信」是两件事。`readPeers` 的返回类型能区分 `absent` / `corrupt` / `recovered`。 |
| **时间是消息的时刻，不是文件的 mtime。** | 永远不要拿文件时间当「上次发消息时间」。 |
| **上限 200 条边，只在写时淘汰**最久未用的。 | 常用会话被淘汰时会话本身还在，只是行尾没有后缀了。 |

## 压缩

| 边界 | 撞上时怎么办 |
|---|---|
| **压缩通知可能永远不来**：DSH 在压缩途中重启，那一次没有完成通知。 | 按「没压」处理，重发一次。 |
| **读不到 token 大小时通知会明说**（这台 DSH 没挂 token 计量器），不是压缩没发生。 | 看有没有 `dsh-token-meter` 在 profile 的 bundles 里。 |
| **同一时刻只能压一个目标一次**：第二次调用回 `already-running`，不排队、不重试。 | 等第一条通知。 |
| **「正在压」只在进程内存里。** 桌面端与 web 是不同进程，互相不知道对方在压同一个目标。 | 那种重复压缩由宿主的 `/compact` 自己报忙，失败原因会进通知。 |
| **宿主报的忙不细分**：这个版本的 backend 会把摘要失败、落盘失败也重包成忙。 | 看目标会话日志里的 `compaction/end{error}`。 |

## 会话与工作区

| 边界 | 撞上时怎么办 |
|---|---|
| **`create_session` 建的会话不会被自动清理。** 误建只能在 GUI 里删，或者用 `archive_sessions` 收走（转录仍在磁盘上）。 | 建之前想清楚要不要 `prompt`；不声明并发安全（两个并发调用可能把已有工作区报成 `[created]`，方向无害）。 |
| **删工作区登记会 orphan 会话。** 会话还在、还能被列出，只是失去侧栏分组。 | 持有会话时默认拒绝，要 `force: true`；持有调用者自己的工作区一律不许删。 |
| **`archive_sessions` 不能归档调用者自己**，没有越过这个限制的开关。 | 要收走自己所在的会话，让别的会话（或你自己在 GUI 里）来。 |
| **子代理不能用这八个工具**（`execute` 期明确拒绝，工具本身对子代理仍可见——那是宿主注册表的事）。 | 子代理该用 `send_message` / `list_agents`。 |

## 升级与卸载

| 边界 | 撞上时怎么办 |
|---|---|
| **升级 DSH 后接口可能对不上**，插件不会自己检查。 | 先 `node scripts/compat-check.mjs`（读 `app.asar` 断言宿主接口，非 0 退出就先别升级），再让一个空闲会话发条消息确认投递仍落地。误诊表见 [AGENTS.md](../AGENTS.md#误诊手册)。 |
| **卸载不回头修改既有转录**：旧会话里仍留着当时注入的系统提示词快照，以及 `source.kind === 'agent-message'` 的历史事件。 | 这类事件不进 `session export`（导出只取 `kind === 'user'`）。 |
| **只把 `enabled` 关掉不算卸载。** | 卸载要删 `dsh.profile.bundles` 与 `dependencies` 两行，再 `pnpm install` 并重启。 |
